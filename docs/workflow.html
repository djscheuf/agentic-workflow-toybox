workflow.js

How the story pipeline runs, step by step, and what each stage does with its files.

Overview

workflow.js takes a user story file and passes it through three agentic analysis steps, each run as a headless Devin CLI call. It then computes a weighted quality score from the final grade. If the score clears the threshold, the workflow completes. If not, the workflow stops and tells the author to revise the story.

The file's header comment describes three stages (setup, agentic, results). In practice the agentic stage runs three times in sequence, and a scoring gate follows them.

Usage

node workflow.js <input-file>

# Optional: point at a different Devin binary (defaults to "devin")
DEVIN_BIN=/path/to/devin node workflow.js docs/add-two-positive-integers.md

Stage by stage

  1. 1Setup setupValidation()

    Resolves the input path and checks that it exists and is a regular file. If either check fails, the script exits with an error. On success it derives a per-story output folder, docs/<stem>/, from the input filename, creates it, and logs both the input path and that folder. The input file itself is never moved. Every later step writes into this folder, so runs on different stories that share an input directory cannot collide.

  2. 2Agentic step: extract-story-intent

    Reads the story and writes an intent.json file that captures what the story is trying to achieve. The input is the original story file. The output becomes the input to step 3.

  3. 3Agentic step: analyze-story

    Takes the intent file and writes an analysis.json file that evaluates the story.

  4. 4Agentic step: grade-story-analysis

    Takes the analysis and writes an analysis-grade.json file. This file must contain a score and a reason for each dimension listed under Scoring.

  5. 5Score gate computeScore()

    Reads the grade file, validates it, computes the weighted score, prints it, and decides whether the story passes. This step does not call the agent. It is plain arithmetic on the grade file.

How each agentic step runs

Every agentic step goes through the same function, agenticCall(). It does the following:

  1. Builds the prompt. The prompt asks the agent to invoke the skill with the same name as the step, on the input file. It tells the agent to write its output JSON and .process/ sentinel into the per-story folder rather than beside the input, and to regenerate its output even if one already exists, so stale results are never reused.
  2. Snapshots the folder. It records the modification time of every file in the per-story output folder that matches the expected output type, such as every *.intent.json file.
  3. Launches the CLI. It runs the following command synchronously, with output inherited from the terminal: 
    devin -p "invoke /<skill> on <input>. Write the output ... into <story-folder> ... Regenerate the output ..." \
     --permission-mode dangerous \
     --respect-workspace-trust false \
     --export <story-folder>/.process/<skill>.atif.json
    The flags do the following: --permission-mode dangerous lets the agent write files, --respect-workspace-trust false is needed for non-interactive runs, and --export saves the conversation trace in ATIF format for later review and cost tracking.
  4. Detects the output. It takes a second snapshot and compares it to the first. Any matching file whose modification time changed is treated as written by this run. If several were written, the most recently modified one is used. If none were written, the step fails.
  5. Verifies the output. It checks that the file exists and is not empty. The step fails if either check does not pass.
The output file is found by modification time, not by name. The agent chooses the file name, and the script only requires that a file with the expected suffix changed during the run. The next step then takes that file as its input.

Scoring

The grade file must contain five dimensions. Each has a score from 0 to 3, a reason, and a recommendation. The script combines them using these weights:

DimensionWeightWhat it measures
business_value0.25Whether the story states a clear value to the business or user
scope0.20Whether the story is appropriately sized and bounded
acceptance_criteria0.25Whether the acceptance criteria are specific and testable
story_format0.15Whether the story follows the expected format
dependencies0.10Whether dependencies are identified

The overall score is (sum of score × weight) / 3 × 100, rounded to two decimals. The threshold is 80. For any dimension that scores 2 or lower, the script prints that dimension's reason and recommendation so the author knows what to fix.

Check this before relying on the score. The five weights add up to 0.95, not 1.00. Because the formula divides by 3 and not by the weight total, a story that scores 3 on every dimension tops out at 95 instead of 100. The threshold still works, but the score does not reach 100 and the ceiling is lower than the printed scale suggests. If the intent is a 0 to 100 scale, one weight needs to rise by 0.05, or the normalization needs to divide by the weight sum.

Exit codes

CodeMeaningTypical cause
0Story passedScore is at or above 80
1Pipeline errorMissing argument or input file, Devin CLI failed to launch or exited non-zero, no output written, empty output, invalid grade file
2PUNCH_OUTScore is below 80. The story needs revision, which is a decision and not a failure

The separate exit code for PUNCH_OUT lets a calling script or CI job tell a weak story apart from a broken pipeline.

Notes and gotchas

  • Trace folder. The ATIF trace is written to .process/ inside the per-story output folder. The script creates the per-story folder but not the .process/ subfolder, so the agent or CLI must create that during the run.
  • Working directory. spawnSync is called with cwd: path.dirname('.'), which always evaluates to .. The CLI therefore runs in the directory where the script was launched, not in the input file's folder. The prompt uses the full input path, so this works, but the option does nothing.
  • Rerunning after a punch out. The script prints the rerun command after a PUNCH_OUT. Every run regenerates all three agentic outputs, so the earlier files are replaced and not reused.
  • Output discovery depends on timestamps. If another process writes a matching file into the same per-story folder during the run, the script may pick it up as this step's output. Per-story folders prevent different stories from colliding, but not a second process writing into the same story's folder.
